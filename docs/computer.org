#+title: Computer Setup Guide

* Overview
This document contains the complete setup guide for a personal Arch Linux system running on a Huawei MateBook X Pro 2021. It covers hardware-specific configurations, system setup, desktop environment configuration, and application installation.

The system uses Hyprland as the primary window manager with a suite of Wayland-native tools for daily computing.

The dorm development host =dorm-dev= dual-boots Windows and Arch, and this
laptop reaches it over Tailscale for SSH, T3 Code, and a streamed Hyprland
desktop. See [[file:remote-dev.org][the dorm-dev guide]] for its NVIDIA, proxy, access, and desktop
setup, which differ from this MateBook-specific setup.

* Hardware-Specific Configuration

** Battery Management (MateBook)
TLP is the power management tool of choice:
#+begin_src shell
systemctl enable tlp --now
#+end_src

In addition to TLP, we also use matebook-applet and huawei-wmi for battery threshold control:
#+begin_src shell
yay -S matebook-applet huawei-wmi
#+end_src

The Huawei applet owns the saved charging thresholds. Install the resume hook
with =sudo ./dotfiles-huawei-wmi/install.sh= from the repository root. Its TLP
drop-in disables TLP's native battery control so the two resume hooks cannot
overwrite each other's settings; TLP still manages power saving. See
[[file:../dotfiles-huawei-wmi/README.md][the Huawei threshold guide]] for installation, verification, and troubleshooting.

** Fingerprint Reader (MateBook)
The built-in sensor is a Goodix =27c6:5125= (USB, power button). As of
2026-09 it is *not supported* by libfprint and has no Linux driver; Goodix
does not publish one. Verified locally: with =fprintd= / =libfprint
1.94.100= installed, =fprintd-enroll= reports "No devices available" (only
the match-on-chip =goodixmoc= driver exists upstream; 5125 is a
match-on-host CDC device). The community reverse-engineering effort at
[[https://github.com/goodix-fp-linux-dev/goodix-fp-dump][goodix-fp-linux-dev]]
is still at the protocol-dump stage for this chip, and the proprietary
Ubuntu/Lenovo Goodix driver only covers =27c6:550a=.

The standard stack (=fprintd=, pulls in =libfprint=) is installed so it
starts working automatically once a driver lands. To re-check after a
system update:
#+begin_src shell
fprintd-enroll   # succeeds once a driver exists; until then: "No devices available"
#+end_src

If it ever gets detected, enroll with =fprintd-enroll= and enable
=pam_fprintd.so= in PAM for sudo / hyprlock.

* Desktop Environment

** Hyprland (Primary)
[[https://wiki.archlinux.org/title/Hyprland][Hyprland]] is a dynamic tiling Wayland compositor.
The active config is =~/.config/hypr/hyprland.lua=. Hyprland prefers it over
=hyprland.conf= after a full session restart; =hyprctl reload= cannot switch
the running session from one config format to the other.

=hypr/hyprland.lua= selects the native =scrolling= layout and loads shared
settings, bindings, and autostart from =hypr/hyprland_common.lua=.
=hyprland_without_hy3.lua= selects =dwindle=; its filename is retained from
the earlier hy3 setup. The Lua entry points do not currently require hy3.
The first window on an empty workspace opens at full width; subsequent
scrolling columns open at 75% width. A =window.open_early= callback selects
=scrolling.column_width= from the destination workspace's window count before
the new column is created. =fullscreen_on_one_column= is disabled so opening
or closing another column preserves existing column widths. =SUPER + W= and
=SUPER + SHIFT + W= cycle the focused column through the configured widths.
=SUPER + Space= runs =script/hypr-window-switcher.sh=, which uses =hyprctl=,
=jq=, and Rofi to select and focus a window across scrolling workspaces.

=misc.focus_on_activate= is enabled in the shared Lua config for both layouts.
This lets applications bring their windows into focus when they request
activation, such as after opening a link or clicking a notification action.
Apply changes with =hyprctl reload= and check
=hyprctl getoption misc:focus_on_activate=; it should report =bool: true=.

*** Idle/Lock (hypridle/hyprlock)
Screen lock and idle management:
#+begin_src shell
sudo pacman -S hyprlock hypridle
#+end_src

Manual controls are separate:

| Shortcut | Action |
|----------+--------|
| =SUPER + SHIFT + I= | Toggle the lid sleep hold (also blocks suspend, as before) |
| =SUPER + I= | Toggle the idle hold: pause automatic locking, screen-off, and idle suspend |
| =SUPER + SHIFT + Esc= | Lock immediately, including while either hold is active |

The holds use =systemd-inhibit= through two user services in =systemd/user/=.
=script/toggle-inhibit.sh lid= and =script/toggle-inhibit.sh idle= toggle them
independently; =script/toggle-inhibit-lid-sleep.sh= keeps the existing lid entry
point. Notifications keep the earlier =Toggled … Inhibition= title and service
=started=/=stopped= wording, reporting success only after the inhibitor is acquired.
Repeated shortcut presses are serialized with =flock= from =util-linux=.

The lid service retains =--what=handle-lid-switch:sleep=; idle locking and
screen-off remain active. The idle service uses =--what=idle=, which Hypridle
respects by default (=general.ignore_systemd_inhibit = false=). Hypridle stays
running, so manual locking and locking before sleep still work. Idle hold alone
allows lid sleep and manual suspend; use both holds to pause both behaviors.
Existing media-player checks remain in place. See the
[[https://wiki.hypr.land/Hypr-Ecosystem/hypridle/][Hypridle configuration]] and
[[https://systemd.io/INHIBITOR_LOCKS/][systemd inhibitor documentation]].

Compare existing units and back up separate files before creating these links:
#+begin_src shell
mkdir -p ~/.config/systemd/user
ln -s ~/dotfile/systemd/user/inhibit-lid-sleep.service ~/.config/systemd/user/inhibit-lid-sleep.service
ln -s ~/dotfile/systemd/user/inhibit-idle.service ~/.config/systemd/user/inhibit-idle.service
systemctl --user daemon-reload
hyprctl reload
#+end_src
Start these services on demand; do not enable them at login. A hold lasts until
toggled off or the user service manager stops. After editing a unit, run
=systemctl --user daemon-reload=; an active hold uses the new unit on its next
start. Toggle a hold and inspect =systemd-inhibit --list= to verify it, or check
=systemctl --user is-active inhibit-lid-sleep.service inhibit-idle.service=.
No Hypridle restart is needed to toggle a hold.

*** Claude Code network guard
=fish/functions/claude.fish= wraps the =claude= command in Fish. Its shared
checker is =script/clash-network-check.fish=. It requires
Clash Verge Rev's running API at =/tmp/verge/verge-mihomo.sock= to report
TUN enabled, =global= mode and a selected Taiwan proxy. Manual selector groups are followed;
automatic/fallback/load-balancing groups and direct routes are rejected.
The Taiwan check uses the selected node's name. Failed or unverifiable checks
block startup; there is no external exit-country request.

Dependencies are Fish, =curl= and =jq=. The function is linked individually into
=~/.config/fish/functions/claude.fish=; other live Fish files stay independent.
On another machine, inspect any existing destination before creating the link:
#+begin_src fish
ln -s ~/dotfile/fish/functions/claude.fish ~/.config/fish/functions/claude.fish
source ~/.config/fish/functions/claude.fish
claude --proxy-check  # check only; does not start Claude
claude               # check, then start; normal Claude arguments are forwarded
#+end_src

New Fish shells autoload it. The wrapper only checks the running configuration
before launching Claude with the existing environment. It does not set proxy
variables or change Clash settings; network routing stays under Clash TUN.
This guards terminal startup only: it does not monitor later Clash changes,
existing/background sessions or launches from other apps.

*** T3 Code network guard
The T3 desktop launcher and its Claude provider use the same TUN/Global/Taiwan
startup check. No wrapper sets proxy variables or changes Clash settings.
=script/t3code-guard.sh= launches the installed =/usr/bin/t3code-nightly= after
the check, and shows a notification if blocked. The launcher override
=t3code/t3code.desktop= is linked at
=~/.local/share/applications/t3code.desktop=; =~/.local/bin/t3code-nightly=
links to the guarded script. =fish/functions/t3.fish= is linked at
=~/.config/fish/functions/t3.fish= and guards the app-owned =t3= CLI in Fish.
Use =t3 --proxy-check= to check without launching the CLI.

T3's =claudeAgent= provider has Binary path set to
=/home/wste/dotfile/script/claude-guard.sh= in
=~/.t3/userdata/settings.json=. The wrapper checks before each Claude process
spawn, including SDK sessions and provider probes, then executes the existing
=~/.local/bin/claude=. It preserves the SDK's standard input/output protocol.
The previous settings file is backed up under
=~/.local/state/dotfile/backups/t3code/=. Other provider settings are preserved.
See [[https://github.com/pingdotgg/t3code/blob/main/docs/user/providers-claude.md][T3's Claude provider settings]].

Restart T3 after changing its provider Binary path so existing sessions use the
guard. New Fish shells load =t3.fish= automatically; an existing shell can run
=source ~/.config/fish/functions/t3.fish=. The installed app and T3's generated
CLI/URL-handler files are unchanged. Direct launches of the installed app and
its generated URL handler can bypass the desktop startup check, while the
configured Claude provider still checks on process spawn. These are startup
checks, not monitoring of existing connections or restrictions on local files.

* Dotfiles Management
This repository contains active desktop configs, separately deployed snapshots,
and preserved utilities. Deployment differs by component; editing a repository
file only changes the live setup when the destination points to that file.

** Maintenance Workflow
1. Inspect =git status --short= and =git diff -- <target-files>=. Preserve
   existing changes and untracked additions. AI agents follow [[file:../AGENTS.md][AGENTS.md]];
   Doom work also follows [[file:../doom/AGENTS.md][doom/AGENTS.md]].
2. Locate the source and its live destination. Use =ls -ld= and =readlink -f=
   to check links; compare independent files before copying or linking them.
   There is no general installer or Stow manifest in this repository.
3. Make a focused source change. Tangle Doom's literate config when needed;
   leave unrelated snapshots, application state, and bundled plugins alone.
4. Check the affected file, deploy it if needed, then reload and verify the
   changed behavior. Documentation-only changes need no desktop reload.
5. Keep this guide aligned with setup/usage changes. Change =AGENTS.md= only
   when a policy update is explicitly requested. Review the scoped diff and
   =git diff --check=.
   Use a focused branch, stage explicit paths, and create GPG-signed
   Conventional Commits. Push the branch and open a pull request with the
   relevant validation. Obtain an independent subagent review, address findings,
   and merge after required checks pass unless the request calls for an
   unmerged pull request.

For example, compare Fish before deploying a change:
#+begin_src shell
readlink -f ~/.config/fish/config.fish
diff -u fish/config.fish ~/.config/fish/config.fish
fish -n fish/config.fish
#+end_src
The =diff= command returns status 1 when the files differ. Resolve the intended
changes on both sides before deployment; a whole-directory copy can overwrite
newer live configuration and shell state.

** Validation
There is no unified test suite. Use checks suited to the edited file:

- Fish: =fish -n <file.fish>=.
- Lua: =luac -p <file.lua>= for syntax, followed by application-specific checks.
- Shell: =sh -n <file.sh>= or =bash -n <file.sh>= according to its shebang.
- systemd user units: =systemd-analyze --user verify <file.service>=.
- TOML/JSON: parse with Python =tomllib= / =json=. Waybar's =config.jsonc=
  contains comments and needs a JSONC-aware parser, such as =json5=.
- Doom: tangle and check Lisp as described in =doom/AGENTS.md=; sync module
  or package changes.
- Vim: =vim -N -n -i NONE -es -u vim/vimrc '+if !empty(v:errmsg) | cquit | endif' '+qall!'=,
  then check the cursor when entering insert mode and returning to normal mode.
- Hyprland: after a deployed config change, inspect =hyprctl configerrors=
  and exercise the affected binding/layout.
- Docs: verify file references and run =git diff --check=.

|----------------+---------------------------------------------|
| Hyprland       | =hyprctl reload= for the current format; session restart for Hyprlang/Lua migration |
| Doom Emacs     | Tangle =config.org=; =doom sync= after =init.el= / =packages.el= changes; reload or restart Emacs |
| Fish           | In Fish, =source ~/.config/fish/config.fish= after deployment |
| Waybar         | =killall waybar && waybar=                   |
| Swaync         | =swaync-client --reload-config= / =swaync-client --reload-css= |
| Ghostty / Yazi / Neovim | Restart the application after deployment |
| Vim            | Restart Vim or run =:source ~/.vimrc=       |
| Rime           | Use the Deploy action in the Fcitx5 Rime menu |
| Rofi           | The next launch reads the config            |
| Lid / idle hold units | =systemctl --user daemon-reload=; toggle an active hold off/on to use an edited unit |

** Application Update Tracking
The repo-local Codex skill at =.agents/skills/check-application-updates/= tracks
installed application versions and reviews available updates against the config
files declared in =.app-update-tracker.json=. Invoke the skill when an update
check is needed; it does not run in the background or install packages.
When hy3 is enabled, Hyprland updates are blocked until hy3's current HyprPM
manifest contains a compatibility pin for the exact target release commit.

- =rofi/= - Application launcher configuration

- =fcitx5/= - Older Pinyin settings; =rime/= - Current Rime customization
- =swaync/=, =starship/= - Notification center and shell prompt configuration

** Source, State, and Backup Files
- =doom/config.el= is generated and ignored by Git; edit =config.org=.
- =fish/fish_variables= is shell-managed state. =nushell/history.txt= is saved
  history, not shell configuration. Review these separately from source changes.
- =fish/fish_variables.rej= and =waybar/style.css.bac= are preserved reject/backup
  files; they are not normal editing entry points.
- =yazi/plugins/= contains bundled third-party code, including local edits.
  Inspect its diff before updating dependencies with =ya pkg=.
