#+title: dorm-dev Remote Development Host

* Overview
=dorm-dev= is a Lenovo Legion Y9000P IRX8H (82WQ: Intel i9-13900HX,
RTX 4090 Laptop GPU with 16 GB VRAM, 64 GB RAM) kept in the dorm. Windows stays
on its own SSD for games; Arch runs development tools, coding agents, and a
Hyprland desktop that is streamed to the MateBook. Only the booted OS runs:
Linux jobs and services stop while Windows is booted.

| Item           | Value                                                          |
|----------------+----------------------------------------------------------------|
| Tailscale host | =dorm-dev=, =100.81.184.110=                                   |
| Allowed client | MateBook =euphonium=, =100.71.241.9=                           |
| Terminal/T3    | OpenSSH over Tailscale, key only                               |
| Desktop        | greetd auto-login → locked Hyprland → Sunshine → Moonlight     |
| Proxy          | Mihomo system service: TUN, Global, =🇨🇳 台湾 07 家宽=         |

Repository files for this host live in [[file:../remote-dev/][remote-dev/]], except the SSH
drop-in in [[file:../ssh/sshd-remote-dev.conf][ssh/]]. System files under =/etc= and =/usr/local= are root-owned
copies; compare them with the repository before replacing either side. The
home-directory configuration links into the =~/dotfile= checkout as on the
laptop.

* Disks and boot
| Disk                   | Contents                                                    |
|------------------------+-------------------------------------------------------------|
| =nvme0n1= Samsung 1 TB | Windows, its ESP and recovery partitions (BitLocker); untouched |
| =nvme1n1= UMIS 1 TB    | Arch: =p1= 1 GiB ESP at =/boot=, =p2= 128 GiB swap, =p3= ext4 root |

systemd-boot on the Linux ESP boots =/boot/loader/entries/arch.conf= with
~resume=UUID=<swap>~ for hibernation; the firmware lists it as Linux Boot
Manager next to Windows Boot Manager. Secure Boot is disabled for the official
Arch image; keep UEFI mode and do not clear the firmware keys. Keep the Arch USB
installer for recovery.

=/etc/mkinitcpio.conf= omits the =kms= hook so the NVIDIA modules load from the
root filesystem after resume rather than from the initramfs. Rebuild with
=sudo mkinitcpio -P= after changing hooks.

* Network access
** Tailscale and firewall
UFW denies incoming traffic except from the MateBook on =tailscale0=: TCP 22
for SSH, and TCP 47984, 47989, 48010 plus UDP 47998–48010 for Moonlight.
Review with =sudo ufw status verbose=. Tailscale manages its own netfilter
rules, so restrict peers in the tailnet policy as well. Disable key expiry for
=dorm-dev= in the Tailscale admin console so the unattended host stays
reachable.

Check the path from the client with =tailscale ping dorm-dev=; a direct
connection is needed for a smooth desktop stream.

** SSH
[[file:../ssh/sshd-remote-dev.conf][ssh/sshd-remote-dev.conf]] is installed as
=/etc/ssh/sshd_config.d/00-remote-dev.conf=: public keys only, no root login,
and =AllowUsers wste@100.71.241.9=. After editing it:
#+begin_src bash
sudo install -m 644 ~/dotfile/ssh/sshd-remote-dev.conf /etc/ssh/sshd_config.d/00-remote-dev.conf
sudo sshd -t
sudo sshd -T | rg -i '^(permitrootlogin|pubkeyauthentication|passwordauthentication|kbdinteractiveauthentication|allowusers) '
sudo systemctl reload sshd
#+end_src
OpenSSH prints these keywords in CamelCase, so match case-insensitively. Keep
an existing session open and test a second login before closing it.

The client's =~/.ssh/config= has a =dorm-dev= entry using =~/.ssh/id_ed25519=
with =StrictHostKeyChecking yes=. Use =tmux new-session -A -s dev= for
terminal work that should survive disconnection, and forward development ports
such as =ssh -N -L 8888:127.0.0.1:8888 dorm-dev=.

Bash remains the login shell, so SSH commands and T3's launcher get POSIX shell
behavior. Interactive Bash shells switch to Fish from the end of =~/.bashrc=,
so terminals and =ssh dorm-dev= behave like the laptop.

* Mihomo proxy
All host traffic leaves through the Taiwan 家宽 node, matching the laptop's
Clash Verge TUN/Global policy.

| Repository source                      | Live copy                                  |
|----------------------------------------+--------------------------------------------|
| =remote-dev/mihomo.service=            | =/etc/systemd/system/mihomo.service=       |
| =remote-dev/mihomo-route.py=           | =/usr/local/libexec/mihomo-route.py=       |
| =remote-dev/mihomo-config.example.yaml= | =/etc/mihomo/config.yaml= (mode 600, real node values) |
| Mihomo release binary                  | =/usr/local/bin/mihomo=                    |

The TUN device =mihomo= uses Global mode and fake-IP DNS. Its
=route-exclude-address= list keeps the tailnet (=100.64.0.0/10=) and private
ranges off the tunnel, so SSH, Moonlight, and Tailscale itself bypass the
proxy. The controller listens only on =/run/mihomo/controller.sock= (group
=wste=). =ExecStartPost= selects the fixed node in =GLOBAL=; =mihomo-route.py
check= verifies TUN, Global mode, and that node.

Check routing:
#+begin_src bash
python /usr/local/libexec/mihomo-route.py check
curl -s https://www.cloudflare.com/cdn-cgi/trace | rg '^loc='   # loc=TW
#+end_src

Changing the TUN or routes can cut off SSH. Arm a rollback first, restart
Mihomo, verify a new SSH login, then cancel the rollback:
#+begin_src bash
sudo systemd-run --unit=mihomo-rollback --on-active=5min /usr/bin/systemctl disable --now mihomo.service
sudo systemctl restart mihomo.service
sudo systemctl stop mihomo-rollback.timer
#+end_src

Pacman's mirror list starts with NYCU (Taiwan) and xTom (Hong Kong), which were
fastest through this route. The =[archlinuxcn]= repository (xTom, then USTC)
provides the same extra packages as on the laptop.

* Coding agents and T3 Code
Codex and Claude Code use their native installers under =~/.local/bin=; T3's
runtime is under =~/.t3/runtime=. =~/.local/guarded-bin/{claude,codex,t3}= link
to [[file:../remote-dev/guarded-command.sh][remote-dev/guarded-command.sh]], which runs the Mihomo check before
starting the real command. =~/.profile= (POSIX login shells, used by T3's SSH
launch) and the top of =~/.bashrc= put =~/.local/guarded-bin= first in =PATH=.
Use =codex --proxy-check= to check without starting a CLI. The laptop's
=fish/functions/claude.fish= and =t3.fish= are not deployed here: they check
Clash Verge's socket, which this host does not have.

Sign in on this host separately rather than copying tokens from the laptop:
=codex login --device-auth=, then =claude= and =/login=.

In T3 on the laptop, add =dorm-dev= under Settings → Connections → Add
environment → SSH. Projects, provider credentials, and agent work then stay on
=dorm-dev=. User lingering is enabled for =wste= so user services keep running
without a login.

* NVIDIA, power, and hibernation
The internal 2560×1600 panel (=eDP-1=) is wired to the Intel iGPU, which is the
boot GPU and runs Hyprland; the RTX 4090 runs =nvidia-open-dkms= for CUDA and
NVENC. =nvidia-utils= blacklists nouveau. Check with =nvidia-smi=.

| Repository source                    | Live copy                                 |
|--------------------------------------+-------------------------------------------|
| =remote-dev/nvidia-power.conf=       | =/etc/modprobe.d/nvidia-power.conf=       |
| =remote-dev/logind-60-remote-dev.conf= | =/etc/systemd/logind.conf.d/60-remote-dev.conf= |

The NVIDIA option keeps video memory across sleep, used by the enabled
=nvidia-suspend=, =nvidia-hibernate=, and =nvidia-resume= services. Check it
with =rg PreserveVideo /proc/driver/nvidia/params=. Closing the lid is ignored
on AC power and suspends on battery. The desktop never suspends on idle.

=systemctl hibernate= writes memory to the swap partition. Resuming needs the
power button: there is no remote wake, so do not hibernate the host from
outside the dorm.

* Desktop and streaming
** Session
[[file:../remote-dev/greetd-config.toml][remote-dev/greetd-config.toml]] is installed as =/etc/greetd/config.toml=. At
boot greetd logs =wste= into =start-hyprland= once; after logging out, tuigreet
asks for a login. =getty@tty1= is disabled in favor of greetd.

The shared [[file:../hypr/hyprland_common.lua][Hyprland config]] reads =/etc/hostname=. On =dorm-dev= it starts
=hyprlock= immediately, uses scale 1.6, runs Hypridle with
[[file:../hypr/hypridle-remote.conf][hypr/hypridle-remote.conf]] (lock after 10 minutes and screen off after 15,
no suspend), and starts Sunshine. Laptop-only programs — the MateBook applet,
Dayline, Gammastep, and OneDrive — start only on the laptop. Unlock with
=wste='s password, locally or through Moonlight.

** Sunshine and Moonlight
Sunshine (=sunshine= from archlinuxcn) runs as the user unit
=app-dev.lizardbyte.app.Sunshine.service=. Hyprland imports its environment
into the user manager and starts the unit; it is not enabled, because this
session does not activate =graphical-session.target=.

| Repository source              | Live copy                           |
|--------------------------------+-------------------------------------|
| =remote-dev/sunshine.conf=     | =~/.config/sunshine/sunshine.conf=  |
| =remote-dev/sunshine-apps.json= | =~/.config/sunshine/apps.json=      |

=capture = kms= reads the panel directly; the package grants Sunshine
=cap_sys_admin= for this. Automatic capture selection otherwise stalls on the
desktop portal, which has no RemoteDesktop interface under Hyprland. Because the
Intel iGPU drives the panel, Sunshine encodes H.264/HEVC with VAAPI rather than
NVENC. The only app is Desktop; its preparation command turns the screen back
on in case Hypridle has blanked it. =~/.config/sunshine/= (mode 700) also holds
the TLS identity, web UI credentials, and paired clients.

The web UI listens on localhost only. From the laptop, run
=ssh -N -L 47990:127.0.0.1:47990 dorm-dev= and open =https://localhost:47990=;
the login is stored privately on the laptop in
=~/.local/state/dorm-dev/sunshine-web-ui=.

On the laptop, Moonlight (see [[file:computer.org][the system guide]]) is paired with
=100.81.184.110=. Start the desktop from Moonlight's host list, or with:
#+begin_src bash
moonlight stream 100.81.184.110 Desktop
#+end_src
Moonlight decodes in hardware only when VAAPI works on the laptop, which needs
=intel-media-driver=; without it, Moonlight falls back to software decoding.
To pair another client, run =moonlight pair 100.81.184.110 --pin NNNN= on it,
then enter the PIN under PIN in the web UI.

Sunshine needs PipeWire for audio; its sockets are enabled for the user. A
user manager that started before PipeWire was installed needs
=systemctl --user daemon-reload= and a socket start, or a reboot.

The Fcitx5 profile and configuration, the Nord themes, Fish's frozen theme and

Emacs is checked out at the laptop's Doom commit; follow
[[file:../doom/AGENTS.md][doom/AGENTS.md]] before upgrading it.

built with =yay=. MateBook hardware tools, Clash Verge, games, and the T3
desktop app are not installed; T3 runs through SSH from the laptop.

Git uses the laptop's configuration, including signed commits, but no signing
key is provisioned on this host. Import or create one before committing here.
